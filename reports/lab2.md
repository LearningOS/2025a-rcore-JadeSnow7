本次实验是 rCore 操作系统的 Chapter 4 练习，主要任务是在引入虚拟内存机制后，重新实现系统调用并新增内存映射功能。

## 功能实现总结

### 1. 重写 sys_get_time 系统调用

**问题**: 引入虚存机制后，原来直接访问用户指针的方式失效了。

**解决方案**: 
- 使用 `translated_byte_buffer` 函数将用户虚拟地址转换为可访问的缓冲区
- 支持跨页的 TimeVal 结构体访问
- 使用 `get_time_us()` 获取微秒级精度的时间

**关键实现**:
```rust
let token = current_user_token();
let ts_buffer = translated_byte_buffer(token, ts as *const u8, core::mem::size_of::<TimeVal>());
```

### 2. 重写 sys_trace 系统调用

**新增功能**: 添加地址访问权限检查机制。

**实现细节**:
- **读取操作** (trace_request = 0): 检查地址是否用户可见且可读，不满足条件返回 -1
- **写入操作** (trace_request = 1): 检查地址是否用户可见且可写，不满足条件返回 -1
- 通过 TaskManager 新增的 `current_addr_readable()` 和 `current_addr_writable()` 函数实现权限检查

### 3. 实现 sys_mmap 系统调用 (ID: 222)

**功能**: 申请匿名内存映射。

**参数验证**:
- `start`: 必须按页大小对齐
- `prot`: 第0-2位分别表示读/写/执行权限，其他位必须为0，且不能全为0
- 检查目标虚存区间是否已被映射

**权限转换**:
```rust
// prot 到 MapPermission 的转换
let mut map_perm = MapPermission::U; // 用户可访问
if prot & 0x1 != 0 { map_perm |= MapPermission::R; } // 可读
if prot & 0x2 != 0 { map_perm |= MapPermission::W; } // 可写  
if prot & 0x4 != 0 { map_perm |= MapPermission::X; } // 可执行
```

### 4. 实现 sys_munmap 系统调用 (ID: 215)

**功能**: 取消虚拟内存映射。

**实现方式**:
- 验证所有要解除映射的页面都已被映射
- 直接从页表中解除映射并释放物理页框
- 从相应的 MapArea 中移除页框记录

## 问答作业

### 1. SV39 页表页表项组成

SV39 页表项（PTE）由64位组成，具体结构如下：

| 位域 | 名称 | 作用 |
|------|------|------|
| [63:54] | 保留 | 必须为0 |
| [53:28] | PPN[2] | 物理页号的高位部分 |
| [27:19] | PPN[1] | 物理页号的中位部分 | 
| [18:10] | PPN[0] | 物理页号的低位部分 |
| [9:8] | RSW | 预留给supervisor软件使用 |
| 7 | D | Dirty位，页面是否被写过 |
| 6 | A | Accessed位，页面是否被访问过 |
| 5 | G | Global位，全局映射 |
| 4 | U | User位，用户态是否可访问 |
| 3 | X | eXecute位，是否可执行 |
| 2 | W | Write位，是否可写 |
| 1 | R | Read位，是否可读 |
| 0 | V | Valid位，页表项是否有效 |

**标志位作用**:
- **V**: 决定页表项是否有效
- **R/W/X**: 控制读/写/执行权限
- **U**: 控制用户态访问权限
- **A/D**: 用于页面替换算法
- **G**: 在TLB中标记全局页面

### 2. 缺页异常

**可能导致缺页的异常**:
- **Instruction Page Fault** (异常号 12): 取指令时页面不存在
- **Load Page Fault** (异常号 13): 读取数据时页面不存在  
- **Store/AMO Page Fault** (异常号 15): 写入数据时页面不存在

**发生缺页时的重要寄存器**:
- **scause**: 存储异常原因码 (12/13/15)
- **sepc**: 存储触发异常的指令地址
- **stval**: 存储引起异常的虚拟地址
- **sstatus**: 存储处理器状态信息

### 3. Lazy 策略的好处

**优势**:
1. **节省物理内存**: 只有实际访问的页面才分配物理内存
2. **加快启动速度**: 程序启动时不需要立即加载所有代码段
3. **提高系统响应性**: 减少不必要的磁盘I/O操作
4. **支持大地址空间**: 可以为程序分配远超物理内存的虚拟地址空间

### 4. 10G 连续内存的页表开销

**估算**:
- 10G = 10 × 2^30 字节 = 10 × 2^30 / 2^12 = 10 × 2^18 个页面
- 每个页表项 8 字节
- 三级页表结构下，大概需要 10 × 2^18 × 8 字节 ≈ **20MB** 的页表空间

### 5. Lazy 策略实现思考

**实现方式**:
- mmap时只记录虚拟地址范围和权限，不立即分配物理页面
- 在VMA(Virtual Memory Area)中记录映射信息
- 缺页时检查VMA，如果地址在合法范围内则分配物理页面并建立映射

**缺页处理**:
1. 检查缺页地址是否在已注册的VMA范围内
2. 如果合法，分配物理页面并建立页表映射
3. 如果不合法，向进程发送SIGSEGV信号

### 6. Swap 策略中的页面失效

**页表项表现**:
- **V位清零**: 表示页面当前不在物理内存中
- **PPN域**: 可用于存储磁盘上的位置信息
- **标志位保持**: R/W/X/U位保持原有权限设置
- 访问时触发Page Fault，操作系统从磁盘加载页面

### 7. 双页表与单页表

**单页表更换时机**:
- 进程切换时更换 satp 寄存器指向新进程的页表

**单页表权限控制**:
- 内核页面的PTE中 **U位为0**，用户态访问时触发异常
- 依靠硬件权限检查机制阻止用户态访问内核页面

**单页表优势**:
- 系统调用时无需切换页表，性能更好
- 内核可以直接访问用户空间数据
- TLB利用率更高，减少页表切换开销

**双页表更换时机**:
- **用户态→内核态**: 系统调用、中断、异常时切换到内核页表
- **内核态→用户态**: 返回用户态时切换回用户页表
- **进程切换**: 切换到新进程的用户页表
