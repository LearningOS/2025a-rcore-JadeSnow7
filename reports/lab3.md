# Lab3 实验报告：进程管理与调度

## 实验概述

本次实验实现了基于rCore的进程管理与调度系统，主要包括：

1. **进程控制块扩展**：为TaskControlBlock添加了priority和pass字段，支持优先级调度
2. **系统调用实现**：实现了sys_spawn（进程创建）、sys_set_priority（优先级设置）等关键系统调用
3. **Stride调度算法**：基于BinaryHeap实现了公平的优先级调度算法，确保高优先级进程获得更多CPU时间
4. **内存管理功能**：实现了sys_get_time、sys_mmap、sys_munmap等内存相关系统调用，支持动态内存映射
5. **虚拟内存处理**：正确处理跨页数据结构的内存访问，如TimeVal结构体可能跨越页面边界的情况

系统能够稳定运行，支持多进程调度，并通过stride算法保证进程调度的公平性。所有功能均通过编译测试，内核能够正常启动并运行用户程序。

## 问答题

### stride算法深入

**问题1：实际情况是轮到p1执行吗？为什么？**

不是，实际情况下会轮到p2执行。

原因分析：
- p1.stride = 255, p2.stride = 250
- p2执行一个时间片后，p2.stride = 250 + 10 = 260
- 由于使用8bit无符号整型存储，260会溢出变成 260 - 256 = 4
- 此时比较：p1.stride = 255, p2.stride = 4
- 按照普通比较器，4 < 255，所以会选择p2执行
- 但按照stride算法的本意，应该选择stride更小的p1执行

这就是stride算法在存在溢出时面临的主要问题：溢出会导致调度顺序错误。

**问题2：为什么要求进程优先级 >= 2？**

要求进程优先级 >= 2 是为了保证 STRIDE_MAX - STRIDE_MIN <= BigStride / 2 这个重要不变式。

简单说明：
1. **stride增长控制**：当优先级 >= 2时，每次stride的增长量最大为 BigStride/2
2. **差值限制**：如果所有进程都按照算法严格执行，任意两个进程的stride差值不会超过 BigStride/2
3. **溢出安全**：在这个约束下，即使发生溢出，我们仍然可以通过特殊的比较器正确判断大小关系
4. **数学原理**：在模运算中，如果两个数的差值小于模数的一半，那么它们的大小关系在溢出前后保持一致

**问题3：Stride比较器实现**

```rust
use core::cmp::Ordering;

struct Stride(u64);

impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        const BIG_STRIDE: u64 = u64::MAX;
        let diff = self.0.wrapping_sub(other.0);
        
        if diff == 0 {
            Some(Ordering::Equal)
        } else if diff < BIG_STRIDE / 2 {
            // self > other (考虑溢出情况)
            Some(Ordering::Greater)
        } else {
            // self < other (考虑溢出情况)
            Some(Ordering::Less)
        }
    }
}

impl PartialEq for Stride {
    fn eq(&self, other: &Self) -> bool {
        false  // 题目要求两个Stride永远不会相等
    }
}
```

**比较器原理**：
- 利用wrapping_sub进行模减法
- 如果差值小于BIG_STRIDE/2，说明self在"数轴"上位于other之后（考虑环形）
- 如果差值大于等于BIG_STRIDE/2，说明发生了溢出，实际上self应该小于other
- 这样就能正确处理溢出情况下的大小比较
