## 问答题

### 1. Stride算法溢出问题分析

**问题**：两个pass=10的进程，使用8bit无符号整形存储stride，p1.stride=255，p2.stride=250，在p2执行一个时间片后，理论上下一次应该p1执行。实际情况是轮到p1执行吗？为什么？

**回答**：
不是，实际情况下轮到的是p2执行。

原因分析：
- p2执行后：p2.stride = 250 + 10 = 260，但由于8bit存储溢出，实际为 260 % 256 = 4
- 此时 p1.stride = 255，p2.stride = 4
- 按照普通的数值比较，4 < 255，所以BinaryHeap会选择p2继续执行
- 这违反了stride算法的设计初衷，因为p1的实际stride值应该更小

这个问题的根本原因是整数溢出导致的比较失效。

### 2. 优先级 >= 2 的必要性

**问题**：为什么要求进程优先级 >= 2？可以证明，在进程优先级全部 >= 2 的情况下，STRIDE_MAX - STRIDE_MIN <= BigStride / 2。

**回答**：
这个限制是为了确保在有限的stride存储空间内，不同进程的stride值不会因为溢出而产生错误的比较结果。

简单说明：
1. **BigStride的作用**：BigStride是一个足够大的常数，用于计算每个进程的步长stride = BigStride / priority
2. **优先级下界的意义**：当priority >= 2时，每次增加的stride <= BigStride / 2
3. **差值控制**：在任意时刻，由于调度的公平性，最快进程和最慢进程的stride差值不会超过一个最大步长，即BigStride / 2
4. **溢出安全**：当STRIDE_MAX - STRIDE_MIN <= BigStride / 2时，即使发生溢出，我们仍然可以通过特殊的比较方法正确判断大小关系

这确保了即使在溢出的情况下，我们也能设计出正确的比较器来维持调度的正确性。

### 3. Stride比较器实现

```rust
use core::cmp::Ordering;

struct Stride(u64);

impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        const BIG_STRIDE: u64 = u64::MAX / 2;
        
        let diff = if self.0 >= other.0 {
            self.0 - other.0
        } else {
            other.0 - self.0
        };
        
        if diff <= BIG_STRIDE {
            // 正常情况，直接比较
            self.0.partial_cmp(&other.0)
        } else {
            // 发生了溢出，反转比较结果
            other.0.partial_cmp(&self.0)
        }
    }
}

impl PartialEq for Stride {
    fn eq(&self, other: &Self) -> bool {
        false
    }
}
```

**实现原理**：
- 当两个stride值的差小于等于BIG_STRIDE时，按正常方式比较
- 当差值大于BIG_STRIDE时，说明发生了溢出，此时较大的数值实际上是较小的stride（已经绕了一圈），所以反转比较结果
- 这样可以正确处理类似 (129 < 255) == true 和 (125 < 255) == false 的情况
