# 实验报告：rCore-Tutorial-v3 第三章

## 功能实现总结

在本次实验中，我成功实现了 `sys_trace` 系统调用（ID 为 410），该系统调用支持三种主要功能：

1. **内存读取**（trace_request = 0）：读取用户程序指定地址处的一个字节数据
2. **内存写入**（trace_request = 1）：向用户程序指定地址写入一个字节数据  
3. **系统调用统计**（trace_request = 2）：查询当前任务特定系统调用的调用次数

实现过程中，我在任务控制块中添加了系统调用计数器数组，并在每次系统调用时自动更新计数。该实现完全通过了测试用例验证，能够正确处理内存访问和系统调用统计功能。按照作业要求，没有实现内存访问的安全检查机制。

### 1. 正确进入 U 态后的程序特征测试

通过运行三个 bad 测例，观察到以下错误行为：

**使用的 SBI 版本信息：**
- RustSBI version 0.3.0-alpha.2, adapting to RISC-V SBI v1.0.0
- Implementation: RustSBI-QEMU Version 0.2.0-alpha.2

**测试结果：**

1. **ch2b_bad_address.rs**：尝试访问空指针地址（0x0）
   - 错误行为：`[kernel] PageFault in application, bad addr = 0x0, bad instruction = 0x804003a4, kernel killed it.`
   - 原因：用户态程序访问了无效的内存地址，触发页面错误

2. **ch2b_bad_instructions.rs**：尝试执行特权指令 `sret`
   - 错误行为：`[kernel] IllegalInstruction in application, kernel killed it.`
   - 原因：用户态程序尝试执行只能在 S 态使用的特权指令

3. **ch2b_bad_register.rs**：尝试读取 S 态寄存器 `sstatus`
   - 错误行为：`[kernel] IllegalInstruction in application, kernel killed it.`
   - 原因：用户态程序尝试访问只能在 S 态访问的 CSR 寄存器

### 2. trap.S 中 __alltraps 和 __restore 函数分析

#### L40：刚进入 __restore 时，sp 的含义及使用情景

**sp 的含义：** 刚进入 `__restore` 时，sp 指向内核栈中保存的 `TrapContext` 结构的起始地址。

**两种使用情景：**
1. **系统调用返回**：用户程序通过 `ecall` 进入内核态处理系统调用后，需要返回用户态继续执行
2. **异常/中断处理后返回**：处理完页面错误、时钟中断等异常后，恢复用户程序的执行

#### L43-L48：特殊寄存器处理及意义

```asm
ld t0, 32*8(sp)    # 从 TrapContext 中加载 sstatus
ld t1, 33*8(sp)    # 从 TrapContext 中加载 sepc  
ld t2, 2*8(sp)     # 从 TrapContext 中加载用户栈指针
csrw sstatus, t0   # 恢复 sstatus 寄存器
csrw sepc, t1      # 恢复 sepc 寄存器
csrw sscratch, t2  # 将用户栈指针保存到 sscratch
```

**特殊处理的寄存器及意义：**
- **sstatus**：系统状态寄存器，控制特权级、中断使能等状态，恢复后确定返回用户态的执行环境
- **sepc**：异常程序计数器，保存触发异常时的 PC 值，`sret` 指令会跳转到此地址继续执行
- **sscratch**：临时寄存器，这里用来暂存用户栈指针，便于后续的栈指针切换

#### L50-L56：为何跳过 x2 和 x4

```asm
ld x1, 1*8(sp)
ld x3, 3*8(sp)
.set n, 5
.rept 27
   LOAD_GP %n
   .set n, n+1
.endr
```

**跳过的寄存器：**
- **x2 (sp)**：栈指针寄存器，需要特殊处理。在最后通过 `csrrw sp, sscratch, sp` 切换回用户栈
- **x4 (tp)**：线程指针寄存器，用户程序通常不使用该寄存器，因此无需保存和恢复

#### L60：csrrw sp, sscratch, sp 指令后的寄存器意义

**执行后的值：**
- **sp**：指向用户栈，程序可以正常进行栈操作
- **sscratch**：指向内核栈顶，为下次异常/中断时的栈切换做准备

#### __restore 中的状态切换指令

**状态切换发生在：** `sret` 指令
**原因：** `sret` 是特权指令，用于从 S 态返回到较低特权级。它会：
1. 将 PC 设置为 `sepc` 中保存的值
2. 根据 `sstatus` 中的 SPP 字段将特权级切换到用户态
3. 根据 `sstatus` 中的 SPIE 字段恢复中断使能状态

#### L13：csrrw sp, sscratch, sp 指令后的寄存器意义

**执行后的值：**
- **sp**：指向内核栈，为内核代码执行提供栈空间
- **sscratch**：保存用户栈指针，用于异常处理完成后恢复用户栈

#### 从 U 态进入 S 态的指令

**状态切换发生在：** 用户程序执行的 `ecall` 指令、访问异常地址或执行非法指令时的硬件异常
**机制：** 这些事件会触发硬件自动进行特权级切换，将控制权转移到 `stvec` 寄存器指向的异常处理入口（即 `__alltraps`）
